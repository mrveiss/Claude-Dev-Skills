When to use: you need the memory-library model, or are deciding where something lives.

# Structure

Hierarchy: library -> room -> shelf -> book (one author) -> chapter -> fact.

| Level | Is | On disk |
|---|---|---|
| Library | The whole view | `<mem>/library/` |
| Room | Kind of content, by use (`REF` reference, `CUR` current work, `ARC` archive) | `library/<room-dir>/` |
| Shelf | One topic (`CI`, `GIT`, `TEST`) | `library/<room-dir>/<shelf-name>/CARD.md` |
| Book | One author's notes on a shelf | `.../<shelf-name>/<author>/` |
| Chapter | One sub-topic, a list of entries | `.../<author>/<chapter-key>.md` |
| Fact | One memory, one file, never moved | `<mem>/<fact>.md` |

- Facts stay at the memory root; chapters and catalogues link to them (so ids, links and `MEMORY.md` keep working).
- `MEMORY.md` stays the resident index; `topics/*.md` stay the flat sources the shelves are built from.
- `library/classes.json` is the class schedule; `library/catalog/` holds the generated catalogues.
- Handovers go to the `CUR` room and superseded rules to `ARC`, so the shelf room holds only live rules.
- Generated files start with a `<!-- generated by memory-library ... -->` marker; build never deletes a file without it.
